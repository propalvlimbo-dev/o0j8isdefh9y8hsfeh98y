# Связь ElytrixClans с сайтом и с ElytrixTalisman

## 1. Топ кланов на сайте

Плагин **не** ходит в интернет и **не** поднимает свой HTTP-порт. Вместо этого он раз в минуту
кладёт готовый снимок в файл:

```
plugins/ElytrixClans/export/clans.json
```

Так сделано намеренно. У вас уже есть плагин-мост **ElytrixSite** с HTTP API на порту 20559 и
HMAC-подписью, и backend сайта ходит именно туда. Если бы ElytrixClans поднял второй порт, его
пришлось бы отдельно закрывать файрволом, отдельно подписывать и отдельно чинить при смене
секрета. Файл — самый дешёвый стык: мосту нужно только прочитать его и отдать в свой ответ.

Настройка в `config.yml`:

```yaml
export:
  enabled: true
  interval-seconds: 60
```

Принудительно перевыгрузить: `/elytrixclan export`.

### Формат файла

Кланы **уже отсортированы** по опыту, поле `place` проставлено — сайту остаётся вывести список
как есть. Внутри клана участники отсортированы по личному вкладу.

```json
{
  "generated_at": 1758400000000,
  "count": 2,
  "clans": [
    {
      "place": 1,
      "name": "Elytrix",
      "owner": "Rooyzee",
      "level": 4,
      "exp": 2150,
      "members_count": 3,
      "pvp": true,
      "members": [
        {"name": "Rooyzee", "role": "Лидер", "exp": 800, "kills": 41, "deaths": 12}
      ]
    }
  ]
}
```

`generated_at` — время генерации в миллисекундах. По нему мост поймёт, что сервер лежит и данные
протухли (например, если файл старше 5 минут — показать последний известный топ, а не пустой).

### Что добавить в ElytrixSite

```java
private static final File CLANS = new File(
        "plugins/ElytrixClans/export/clans.json");

// в обработчике HTTP-запроса, например POST /clans/top
String json = new String(Files.readAllBytes(CLANS.toPath()), StandardCharsets.UTF_8);
// отдать как есть — файл уже валидный JSON
```

Файл пишется атомарно (через временный + `ATOMIC_MOVE`), поэтому читатель никогда не поймает
половину записи и городить блокировки не нужно. Читать можно в любом потоке.

Дальше на стороне Go-backend — ещё один путь в `plugin.Request(...)`, рядом с существующими,
и обычный `json.Unmarshal` в структуру.

### Если удобнее база

В `DEPLOY.md` у вас уже поднят MySQL для плагина-моста. При желании мост может не отдавать файл
напрямую, а раз в минуту заливать его содержимое в таблицу — тогда сайт переживёт остановку
Minecraft-сервера. Логика чтения при этом не меняется.

## 2. Награды за талисман

Награды считает и выдаёт **ElytrixClans**. ElytrixTalisman должен только сообщить, кто удерживал
точку — остальное (клановый опыт, личный вклад, монеты, объявление) сделает клановый плагин.

### Как звать

Вариант без зависимости при компиляции — команда от консоли:

```
/elytrixclan talisman <ник1> [ник2] [ник3] ...
```

```java
Bukkit.dispatchCommand(Bukkit.getConsoleSender(),
        "elytrixclan talisman " + String.join(" ", holderNames));
```

Вариант из кода, если ElytrixTalisman собирается вместе с кланами:

```java
TalismanRewards.Result result = TalismanRewards.reward(holderNames);
if (!result.isSuccess()) getLogger().warning(result.getError());
```

Список может содержать игроков из разных кланов и повторы — плагин сам оставит уникальных
участников победившего клана. Клан определяется по первому игроку, у которого он есть.

### Как делятся награды

```yaml
talisman:
  clan-exp: 150.0        # опыт клану — ОДИН раз за победу
  exp-per-holder: 50.0   # личный вклад каждому захватчику
  money-pool: 30000.0    # призовой фонд, делится между захватчиками
  money-min-share: 2500.0
  announce: true
```

Здесь два сознательных решения, и на них стоит остановиться, потому что вы спрашивали про
«3 игрока и ещё 3 места».

**Клановый опыт не умножается на число захватчиков.** Если давать по 150 каждому, то клан из
десяти человек за тот же самый талисман получит 1500, а клан из трёх — 450. Топ тогда меряет не
силу клана, а его численность, и захват превращается в «притащи на точку весь состав». Поэтому
за победу клан получает фиксированные 150 опыта, сколько бы человек ни стояло на точке.

**Монеты — это общий призовой фонд, а не выплата каждому.** По той же причине. На дефолтных
цифрах:

| Захватчиков | Клану опыта | Вклад каждому | Монет каждому |
|---|---|---|---|
| 1 | 150 | 50 | 30 000 |
| 2 | 150 | 50 | 15 000 |
| 3 | 150 | 50 | 10 000 |
| 6 | 150 | 50 | 5 000 |

Обратите внимание: ваш вариант «по 50 очков + по 10к каждому» — это ровно строка с тремя
захватчиками. То есть привычные вам цифры сохранились, но теперь они не ломаются, когда на точку
придёт не три человека, а один или восемь.

Личный вклад (`exp-per-holder`) даётся каждому и на топ не влияет — это внутренняя статистика
клана, по ней растут роли (Стажёр с 50, Опытный с 200). Здесь равная выплата уместна: вклад
отражает участие конкретного игрока.

`money-min-share` страхует от вырождения: при толпе захватчиков доля не упадёт ниже 2500.
Учтите, что при этом суммарная выплата превысит `money-pool` — если это нежелательно, поставьте
её в 0.

Монеты кладутся и офлайн-игрокам: захватчик мог выйти сразу после ивента.

## 3. Модератор и приглашения

Модератору выдано право `INVITE`. Теперь он может `/clan invite`, кикать, переключать PvP и
менять подсветку. Право лидера на передачу клана и роспуск не затронуто.

## 4. Кнопки приглашения

Убраны `☁ »` и разделитель. Теперь это две чистые кнопки с отступом:

```
        ПРИНЯТЬ     ОТКЛОНИТЬ
```

Правится в `config.yml`: `inviteButtonsPrefix`, `inviteAcceptButton`, `inviteDeclineButton`.
