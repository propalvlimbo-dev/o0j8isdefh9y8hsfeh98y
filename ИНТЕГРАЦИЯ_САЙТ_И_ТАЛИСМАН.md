# Связь ElytrixClans с сайтом и с ElytrixTalisman

## 1. Топ кланов на сайте

Плагин **не** ходит в интернет и **не** поднимает свой HTTP-порт. Вместо этого он раз в минуту
кладёт готовый снимок в файл:

```
plugins/ElytrixClans/export/clans.json
```

Так сделано намеренно. У вас уже есть плагин-мост **ElytrixSite** с HTTP API на порту 20559 и
HMAC-подписью, и backend сайта ходит именно туда. Если бы ElytrixClans поднял второй порт, его
пришлось бы отдельно закрывать файрволом, отдельно подписывать и отдельно чинить при смене
секрета. Файл — самый дешёвый стык: мосту нужно только прочитать его и отдать в свой ответ.

Настройка в `config.yml`:

```yaml
export:
  enabled: true
  interval-seconds: 60
```

Принудительно перевыгрузить: `/elytrixclan export`.

### Формат файла

Кланы **уже отсортированы** по опыту, поле `place` проставлено — сайту остаётся вывести список
как есть. Внутри клана участники отсортированы по личному вкладу.

```json
{
  "generated_at": 1758400000000,
  "count": 2,
  "clans": [
    {
      "place": 1,
      "name": "Elytrix",
      "owner": "Rooyzee",
      "level": 4,
      "exp": 2150,
      "members_count": 3,
      "pvp": true,
      "members": [
        {"name": "Rooyzee", "role": "Лидер", "exp": 800, "kills": 41, "deaths": 12}
      ]
    }
  ]
}
```

`generated_at` — время генерации в миллисекундах. По нему мост поймёт, что сервер лежит и данные
протухли (например, если файл старше 5 минут — показать последний известный топ, а не пустой).

### Что добавить в ElytrixSite

```java
private static final File CLANS = new File(
        "plugins/ElytrixClans/export/clans.json");

// в обработчике HTTP-запроса, например POST /clans/top
String json = new String(Files.readAllBytes(CLANS.toPath()), StandardCharsets.UTF_8);
// отдать как есть — файл уже валидный JSON
```

Файл пишется атомарно (через временный + `ATOMIC_MOVE`), поэтому читатель никогда не поймает
половину записи и городить блокировки не нужно. Читать можно в любом потоке.

Дальше на стороне Go-backend — ещё один путь в `plugin.Request(...)`, рядом с существующими,
и обычный `json.Unmarshal` в структуру.

### Если удобнее база

В `DEPLOY.md` у вас уже поднят MySQL для плагина-моста. При желании мост может не отдавать файл
напрямую, а раз в минуту заливать его содержимое в таблицу — тогда сайт переживёт остановку
Minecraft-сервера. Логика чтения при этом не меняется.

## 2. Награды за талисман

ElytrixTalisman уже подключён к кланам напрямую (`libs/ElytrixClans-1.0.jar`), поэтому связка
сделана вызовом API, без команд и без дублирования настроек.

### Что было сломано

`ClanService.addPoints()` вызывал `clan.setPoints(...)` — **поинтов в кланах больше нет**, мы
вырезали их, когда переводили магазин на монеты Vault. Талисман в текущем виде просто не
скомпилировался бы против актуальных кланов. Заодно `addExp()` дёргал `clan.setExp()` напрямую,
в обход `addClanExp()`: опыт начислялся, но проверка уровня не срабатывала, и клан не получал
сообщение о повышении.

Обе вещи убраны. Теперь награды выдаёт одна точка — `TalismanRewards.rewardPlace()`.

### Кто считается захватчиком

`PlayerParticipationTracker` раньше хранил только `Set<UUID>` и **сбрасывался при каждой выдаче
лута** — по нему нельзя было понять, кому платить в конце. Теперь он ведёт два независимых
счёта:

- `currentSegment` — отрезок до следующей выдачи лута, сбрасывается как и раньше;
- `sessionHolders` — клан → ники захватчиков **за всю сессию**, сбрасывается только на старте.

Игрок попадает в список в том же тике захвата, где ему начисляются очки клану, то есть ровно
тогда, когда он реально стоял в радиусе и был жив.

### Как делятся награды

Размеры задаются в `config.yml` **кланов** (секция `talisman.places`), а не в `rewards.yml`
талисмана — иначе одни и те же числа жили бы в двух плагинах. В талисмане осталось только
`reward-places: 3`.

```yaml
talisman:
  announce: true
  places:
    1:
      clan-exp: 500.0        # опыт клану — один раз за место
      exp-per-holder: 50.0   # личный вклад каждому захватчику
      money-pool: 30000.0    # призовой фонд места, делится между захватчиками
      money-min-share: 0.0
    2: { clan-exp: 300.0, exp-per-holder: 30.0, money-pool: 15000.0 }
    3: { clan-exp: 150.0, exp-per-holder: 15.0, money-pool: 7500.0 }
```

Здесь два сознательных решения — вы спрашивали про «3 игрока и ещё 3 места».

**Клановый опыт не умножается на число захватчиков.** Иначе клан из десяти человек за тот же
талисман получит вдесятеро больше, чем клан из трёх, и топ будет мерить численность, а не силу.

**Монеты — фонд места, а не выплата каждому.** По той же причине. Для первого места:

| Захватчиков | Клану опыта | Вклад каждому | Монет каждому |
|---|---|---|---|
| 1 | 500 | 50 | 30 000 |
| 2 | 500 | 50 | 15 000 |
| 3 | 500 | 50 | **10 000** |
| 6 | 500 | 50 | 5 000 |

Ваш вариант «по 50 очков + по 10к каждому» — это ровно строка с тремя захватчиками. Цифры
сохранены, но больше не ломаются, когда на точку придёт один человек или восемь.

Личный вклад даётся каждому и на топ не влияет: это внутренняя статистика клана, по ней растут
роли (Стажёр с 50, Опытный с 200). Здесь равная выплата уместна.

Если захотите «по 10к каждому независимо от количества» — поставьте `money-pool: 0` и
`money-min-share: 10000`.

### Вызов из кода

```java
TalismanRewards.Result r = TalismanRewards.rewardPlace(clanName, holders, place);
```

Список может содержать чужаков и повторы — останутся уникальные участники нужного клана.
Клан-победитель получает опыт даже если поимённый список пуст (например, все вышли с сервера).

Для плагинов без зависимости есть команда:

```
/elytrixclan talisman <место> <клан> [ник1 ник2 ...]
```

### ВАЖНО: пересоберите в правильном порядке

`ElytrixTalisman/libs/ElytrixClans-1.0.jar` датирован 11 августа, в нём **нет** класса
`TalismanRewards`. Если собрать талисман против него, сборка упадёт с `cannot find symbol`.

```bash
# 1. сначала кланы
mvn -f pom.xml clean package
# 2. свежий jar кладём в libs талисмана
cp target/ElytrixClans.jar ElytrixTalisman/libs/ElytrixClans-1.0.jar
# 3. только теперь талисман
mvn -f ElytrixTalisman/pom.xml clean package
```

Учтите: в `pom.xml` талисмана указан `java.version` 17, а кланы собираются под Java 8. Это
допустимо (плагин 17 читает классы 8), но сам сервер тогда обязан быть на Java 17 — у вас в
`DEPLOY.md` так и есть, с флагами `-DPaper.IgnoreJavaVersion=true`.

## 3. Модератор и приглашения

Модератору выдано право `INVITE`. Теперь он может `/clan invite`, кикать, переключать PvP и
менять подсветку. Право лидера на передачу клана и роспуск не затронуто.

## 4. Кнопки приглашения

Убраны `☁ »` и разделитель. Теперь это две чистые кнопки с отступом:

```
        ПРИНЯТЬ     ОТКЛОНИТЬ
```

Правится в `config.yml`: `inviteButtonsPrefix`, `inviteAcceptButton`, `inviteDeclineButton`.
